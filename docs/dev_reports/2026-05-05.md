## 2. Auth UX polish

A series of small visual tweaks driven by direct review of the live UI:

- **Logo glow** — removed the green glow ring on the logo box at the top
  of the sign-in card; left only the standard project drop shadow.
- **Login button** — iterated several times on the at-rest border + glow
  treatment (started at green border + glow, ended at `var(--blue)` border
  with no glow at rest, hover transitions border + text to `var(--green)`
  with no shadow). Width capped to 60-70% of the form column and centered.
- **Field labels** — removed the redundant "Login" / "Password" labels
  above each input. Placeholders now carry the labeling.
- **Placeholder + typed value colors** — placeholders in `var(--green)`,
  typed values in `var(--green)`, both via a `blendedInputSx` recipe that
  overrides the global `OutlinedInput` theme just for the auth inputs.
- **Field eye / clear icons** — eye toggle on the password field and a
  new clear-X icon on the email field, both sitting at rest in
  `var(--blue)` and brightening to `var(--green)` on hover via a shared
  `inputAdornmentIconSx` recipe.
- **Right panel** — content collapsed to a single line "Welcome to
  PheNode" with a subtitle "Environmental Intelligence Platform" in
  `var(--blue)`. Background experimented through several variants; final
  is a subtle radial gradient anchored at top-center.
- **Auth pill** — the centered pill on desktop sits on a gradient page
  background with a `var(--reflected-light)` border and the project's
  standard drop shadow. On mobile the pill goes full-bleed with no
  rounded corners and no border so the page background never shows
  through at the edges.
- **Footer** — added "Copyright © 2026 Agrela Ecosystems. All rights
  reserved" anchored at the bottom of the page background, hidden on
  mobile. Only the "Agrela Ecosystems" portion is the link to
  `https://www.agrelaeco.com`.
- **Accessibility nit** — the LOGIN button's `aria-label` was changed
  from `"Sign in with email and password"` to
  `"Login — sign in with email and password"` so it now contains the
  visible "LOGIN" text (WCAG 2.5.3, "Label in Name").

## 3. Header avatar menu — wired to real user

The avatar dropdown in the dashboard header was previously hardcoded to
"Bill Keezle / Super User Account" with a non-functional logout button.

**What changed:**

- New shared utility `src/utils/auth.js` exporting:
  - `decodeJwtPayload(token)` — base64url-decode and parse a JWT payload.
  - `getCurrentUser()` — read `access_token` from `localStorage`, return
    `{ email, role, isApproved, orgId, exp }` or `null`.
  - `formatRoleLabel(role)` — `USER` / `ADMIN` / `SUPER_ADMIN` →
    "User Account" / "Admin Account" / "Super Admin Account".
  - `clearTokens()` — remove `access_token` and `refresh_token` from
    `localStorage`.
  - `logout(navigate)` — clear tokens then route to `/login`.
- `Profile/index.jsx` reads from `getCurrentUser()` and renders the
  email as the username line and the formatted role as the secondary
  line. Both lines collapse to flex with `noWrap` + ellipsis so a long
  email truncates instead of pushing the logout button off the right
  edge.
- `AuthApprovalPending.jsx` was refactored to use the shared
  `getCurrentUser` and `logout` helpers, removing ~30 lines of
  duplicate boilerplate.
- The popper paper was rebuilt around the same radial gradient as the
  drawer's `SHELL_SURFACE_GRADIENT` for visual continuity. Hit several
  dead-ends along the way (a phantom white overlay traced to the
  `MainCard` component painting its own gradient on top of the consumer
  `sx`; tabs picking up MUI's default white hover background; backdrop
  filter creating a frame-1 flash during the Grow transition), all
  resolved.
- All sub-components (Tabs, ProfileTab list, SettingTab list, divider,
  user-info row, logout icon button) use only project tokens — no white
  text anywhere, no MUI grays, no template-leftover chrome.
- The "Logout" entry that the `ProfileTab` list used to have was removed
  during cleanup, then restored after the user requested it; it shares
  the parent's `handleLogout` via an `onLogout` prop so both affordances
  fire the same close-popper-then-clear-tokens sequence.

## 4. Login wired to the real backend

`AuthLogin.jsx`'s `handleEmailLogin` had been a UI-only stub. Verified
the phenodeX auth router actually exposes the email/password endpoints
(`POST /api/auth/login`, `POST /api/auth/signup`, plus the existing
Google flow), then wired the form:

- 200 response → store `access_token` + `refresh_token` in
  `localStorage`, navigate to `/dashboard/fleet-overview` with replace.
- 403 with `detail` containing "pending" → navigate to
  `/approval-pending`.
- 401 / other 4xx → render an inline themed `Alert` (using
  `var(--critical)` token), keep the form editable.
- Network error → render the same Alert with "Network error — please
  try again."
- Submit button shows "Signing in..." and is `disabled` while the
  request is in flight.

`.env` re-organized with both candidate `VITE_API_URL` values (local
and production) and an explanatory header documenting that both
environments mount routes at plain `/api` (no `/v1` segment). The
incorrect `/api/v1` claim from earlier in the day was tracked back to a
verbal source, verified against `phenodeX/docs/frontend-backend-api.md:16`
and `phenode_backend/main.py:108-116`, and corrected. The `.env` file
is now untracked from git (was committed previously) and there's a
companion `.env.example` template that IS tracked.

## 7. Lighthouse — setup, iteration, results

### 7.1 Setup

- Installed `lighthouse@^12.0.0` as a devDependency in
  `phenodeV3/package.json`.
- Added three npm scripts: `audit:login`, `audit:register`, `audit`
  (chained `&&`).
- Wrote `scripts/lighthouse-audit.sh` and the `make audit` Makefile
  target.
- Documented the whole thing in `phenodeV3/docs/Lighthouse/instructions.md`
  (12 numbered sections covering what Lighthouse is, how to run it,
  what each command flag does, troubleshooting, and how to extend).

### 7.2 The iteration loop

Five rounds of audits today. The change log captures each:

| Round | What changed | Performance | FCP | LCP | Unused JS |
| ----- | ------------ | ----------- | --- | --- | --------- |
| 1 | Initial baseline | 86 | 3.0 s | 3.4 s | 105 KiB |
| 2 | Applied all 5 audit-driven fixes | 79 | 3.8 s | 4.0 s | 229 KiB |
| 3 | Reverted CSS deferral (`media="print"`) | 80 | 3.3 s | 4.1 s | 229 KiB |
| 4 | Reverted `manualChunks` for x-charts/pickers | 88 | 2.9 s | 3.2 s | 105 KiB |
| 5 | Inline CSS plugin + lazy `DashboardLayout` | **91** | **2.7 s** | **2.9 s** | **50 KiB** |

### 7.3 What worked

- **Conditional ResizeObserver polyfill** — wrapped in
  `if (!('ResizeObserver' in window))`. Modern browsers skip the request
  entirely. Removed an 802 ms render-block from the third-party CDN.
- **Real `robots.txt`** — added `phenodeV3/public/robots.txt`. SEO
  92 → 100. The previous "44 syntax errors" audit was Lighthouse parsing
  the SPA's `index.html` as robots directives because the server was
  routing every path through the React app.
- **`aria-label` containing visible text** — the LOGIN button now reads
  `"Login — sign in with email and password"`. Cleared
  `label-content-name-mismatch`.
- **Inline entry CSS via custom Vite plugin** — wrote a small
  `inlineEntryCss()` build-only plugin that swaps `<link rel="stylesheet">`
  for an inline `<style>` and deletes the orphan CSS file from `dist/`.
  Eliminated the render-blocking CSS request entirely without the FOUC
  that the `media="print"` trick produced.
- **Lazy-load `DashboardLayout`** — wrapped in
  `Loadable(lazy(() => import('layout/Dashboard')))` in `MainRoutes.jsx`.
  Entry chunk shrunk 244 KB → 148 KB (−39 %). Unused JS halved.

### 7.4 What didn't work

Recorded for future reference in
`phenodeV3/docs/Lighthouse/baseline.md` § 5:

- **`media="print" onload="this.media='all'"` CSS deferral.** Satisfied
  the audit but caused FOUC on the auth surface (which depends on CSS
  for first paint due to `backdrop-filter` and gradients). FCP regressed
  by 800 ms. Reverted.
- **Object-form `manualChunks` for lazy-only deps** — declared
  `mui-charts` and `mui-pickers` chunks for `@mui/x-charts` and
  `@mui/x-date-pickers`. Did shrink the entry bundle, but the chunks
  ended up loaded as `High`-priority static deps on every route
  including `/login`. Net result was MORE JS shipped to auth pages.
  Even `modulePreload: { resolveDependencies: () => [] }` didn't
  suppress the eager fetch. Reverted.

### 7.5 Final scores

```
Performance:    91   (+5 vs baseline)
Accessibility:  100  (held; lone failing audit cleared)
Best Practices: 100  (held)
SEO:            100  (+8 vs baseline)
```
